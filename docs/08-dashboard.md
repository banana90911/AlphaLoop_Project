## 8. 대시보드
시스템/자본 상태를 확인하는 도구

### 8.1 지켜야 할 경계
- 읽기 전용
- 로그인도 DB에 저장하지 않는다.
- 시스템은 대시보드의 존재를 모른다. 둘은 DB로만 만난다.

### 8.2 "최신 상태"의 정의
- 브라우저가 60초마다 API를 다시 호출해 화면을 갱신한다. 페이지 전체를 새로 그리지 않고 바뀐 값만 다시 그린다.
- 화면 상단에 마지막 업데이트 시간 표시

### 8.3 기술
① — 백엔드는 `FastAPI` + `uvicorn`
② — 프론트는 `React` + `Vite` + `Tailwind CSS`
③ — 화면과 서버는 따로 배포한다. 화면은 Vercel, API와 DB는 NCP 서버.

차트 라이브러리는 **ECharts**로 정했다. 자본 곡선이 요구하는 것 — 확대·좌우 스크롤, 확대한 구간에 세로축을 다시 맞추기, 한 곡선 위에 성격이 다른 마커(체결·이체) 얹기 — 이 셋을 라이브러리 밖에서 손으로 만들지 않아도 되는 것이 ECharts뿐이었다. npm 의존성으로 번들에 넣고 실행 중에 외부에서 불러오지 않는다. 외부 요청 0이 원칙이라 글꼴도 CDN에서 받지 않고 기기에 있는 것만 쓴다.
백엔드 계약(조회 + JSON)은 프론트가 무엇이든 바뀌지 않는다. 그래서 API를 먼저 만들고 화면을 나중에 갈아엎어도 백엔드는 그대로다.

### 8.4 화면 구성
네 영역을 한 페이지에 놓는다. 페이지 이동이나 탭 전환 없이 스크롤만으로 전부 본다.

- 값이 오르면 빨강, 내리면 파랑으로 통일한다.
- 보유 종목이 20개까지 늘어난다.

**① 나의 정보 — 잔고·보유 종목·평가손익**
- 계좌 현황 : 총자본, 예수금, 평가손익, 당일 손익률
- 누적 순입금 : 개시 이후 내가 넣은 돈에서 뺀 돈을 뺀 값(`AccountSnapshots.CumulativeNetFlow`). `총자본 − 누적 순입금 = 누적 손익`이라 두 숫자가 서로를 검산한다.
- 누적 손익(TWR) : 이체 효과를 제거한 시간가중수익률(`TwrIndex − 1`). 총자본은 입금하면 그냥 뛰지만 이 숫자는 안 흔들린다 — 비율로 성과를 볼 때는 항상 이쪽을 본다.
- **안전 출금 가능액 : `예수금 − 미체결 매수 주문 금액`.** 이만큼까지는 빼도 미수가 안 난다. 미체결 매수는 아직 돈이 안 나갔을 뿐 이미 쓰기로 정해진 돈이라 먼저 뺀다. 폰에서 이체 전에 이 숫자를 보는 것이 미수를 막는 실질적으로 유일한 수단이다.
- 평가손익 : `Positions.AveragePrice` vs 마지막 사이클이 본 가격(`CycleScores.LastPrice`). + 그 사이클 시각.
- 보유 종목은 한 줄에 한 종목 — 종목명, 수익률(+색깔), 아랫줄에 평단, 보유일수, 수량(`Positions`(`status='open'`)), 손절가.
- 보유가 20종목까지 가므로 기본은 상위 5줄만 펼쳐 두고 나머지는 "더보기"로 접는다.

**② 수익 그래프 — 시간순 누적 + 벤치마크**
- 세로축 토글 3개. 금액과 비율이 이체에 다르게 반응하기 때문에 하나로는 못 그린다.

  | 축 | 무엇을 그리나 | 이체가 보이나 |
  | - | - | - |
  | `실현손익 누적` (기본) | `Outcomes.NetProfitLoss`를 청산일 순으로 누적 | **아니오** — 마커도 안 찍는다 |
  | `총자산` | `AccountSnapshots.TotalAsset` 시계열 | 예 — **여기에 입출금 마커** |
  | `TWR 지수` | `AccountSnapshots.TwrIndex` | 이체 시점에 회색 세로 점선 |

- 실현손익 축에 입출금 마커를 안 찍는 이유는 그 축이 이체와 무관하기 때문이다. 찍으면 없는 인과를 암시한다.
- 입출금 마커는 매수·매도 점(초록·빨강)과 구분되게 **회색 삼각형**으로 그린다 — 입금 ▲, 출금 ▼. 툴팁은 `입금 / 금액: +2,000,000원`.
- 배당·이자·세금 환급은 이체 마커로 찍지 않는다. 그건 수익이라 곡선 안에 이미 들어 있다.
- 호버 툴팁 : 그 거래의 날짜, 종목, 실현손익, R 배수(`rMultiple`).
- 곡선 위에 매수·매도 시점을 점으로 찍는다(초록·빨강). 어느 구간의 상승이 어느 거래에서 나왔는지 눈으로 잇는 용도다.
- 벤치마크 겹쳐 그리기 : `MarketIndices`의 코스피·코스닥 + 균등가중 워치리스트. 우리 전략이 비용 떼고 이들을 이기는지 한눈에 본다.
- 기간 토글은 일, 월, 년, 전체.
- 확대 및 좌우로 스크롤 가능. 확대 시 보여지는 부분을 토대로 그래프 상단/하단에 맞춘다.

**③ 거래 리포트 — 목록 + 근거 펼침**
- 목록 : `Orders`·`Positions`·`Outcomes`에 **`CashFlows`를 합쳐** 시간순으로 한 행씩. 열은 날짜, 시각, 구분(매수/매도/입금/출금), 종목(+종목코드), 단가, 수량, 거래대금, 손절가, 상태(보유/청산). 날짜 필터와 전체/매수/매도/**입출금** 토글로 좁힌다.
- 거래대금은 매수면 음수(초록), 매도면 양수(빨강)로 부호를 붙여 현금이 어느 쪽으로 움직였는지 바로 읽히게 한다. **입출금도 같은 규칙을 그대로 잇는다** — 거래대금이 곧 현금 방향이므로 입금 +, 출금 −.
- 입출금을 여기 섞는 이유는 "이 구간에 왜 돈이 늘었나"를 한 화면에서 설명하기 위해서다. 매매와 이체가 따로 놀면 그 인과를 사람이 못 잇는다.
- 펼침 — 입출금 행: 기대 예수금 vs 실제 예수금, 감지한 사이클, 확인 상태(`unconfirmed`/`confirmed`/`reclassified`).
- 펼침 — 진입 근거: `Decisions`의 점수·적용 임계·손절가·R·목표 보유 수·수량·기대 엣지, `CycleScores`의 항목별 백분위(모멘텀·수급·거래대금 증가·저변동성)와 레짐.
- 펼침 — 게이트 결과: `RiskChecks`에서 어느 관문에 걸려 거부·축소됐는지.
- 펼침 — 청산 결과: `Outcomes`의 실현손익·보유일수·청산 사유(`exitReason`).
- 이 근거들은 전부 숫자라 행 크기가 작다. 압축·삭제 없이 영구 보존하므로 몇 년 전 거래도 근거가 그대로 남는다.

**④ 오류·정지 알림**
- `SafeStopEvents` — 발생 시각·원인·해제 여부. 비어 있는 `releasedDateTime`이 곧 "지금 정지 중"이다.
- `Cycles` — `failed`·`skipped` 사이클과 실패 단계.
- `IngestRuns` — 일일 배치 결과. `failed`·`partial`이면 그날 데이터가 낡았다는 뜻이라 눈에 띄게 표시한다.
- `CashFlows`(`Status='unconfirmed'`) — **미분류 현금 변동**. 이건 **정보성 항목이다.** 매매를 막고 있는 게 아니라 라벨이 아직 안 붙었다는 안내일 뿐이다. 여기 뜨는 진짜 차단은 미수와 50% 유출 SafeStop 둘뿐이다.
- 행을 고르면 원인과 무엇을 확인하고 어떻게 해제하는지를 함께 보여준다. 보유 불일치·데이터 오류는 사람 개입 해제가 필수다.
- 미분류 현금 변동에는 붙이는 방법만 안내한다 — `python -m ops.cashflow confirm --id <FlowId> --kind deposit`. 대시보드는 읽기 전용이라 여기서 라벨을 붙일 수 없다(8.1).
- 대시보드는 읽기 전용이라 해제 버튼을 누르는 곳이 아니다 — 무엇을 해야 하는지 알려주는 곳이다.


### 8.5 어디서 읽고 어떻게 접속하나
- 매매 cron·DB·대시보드 API가 같은 NCP 서버에서 돈다. 대시보드는 같은 DB를 `SELECT` 전용 계정으로 읽으므로, 매매 코어가 기록하는 중에도 읽기가 막히지 않는다.
- 화면은 Vercel에 있고, 화면이 보내는 조회 요청은 Tailscale Funnel을 지나 서버로 간다. 도메인을 사지 않고도 전 구간이 암호화된다.
- 어느 기기에서든 브라우저로 접속한다. 폰에서도 같은 화면을 본다. 접속 전에 따로 준비할 것이 없다.
- 주소를 아는 사람이 있어도 로그인 없이는 아무것도 보지 못한다.
- **브라우저에게는 화면과 API가 같은 주소로 보인다.** Vercel이 `/api/*` 요청을 받아 Funnel 주소로 넘기기 때문이다(10.12). 그래서 브라우저의 교차 출처 차단에 걸리지 않고, 출입증 쿠키도 화면과 같은 주소의 1차 쿠키가 되어 그냥 실려 간다 — 서버 쪽에 따로 열어 줄 것이 없다.
- 화면에서 API 주소를 직접 부르는 방식으로 바꾼다면(Vercel을 안 쓰거나 넘기기를 안 쓸 때) 그때는 서버 `.env`의 `DASHBOARD_ALLOWED_ORIGINS`에 화면 주소를 적어야 한다. 비워 두는 것이 기본이고, 비어 있으면 아무 데도 열지 않는다. 와일드카드는 쓰지 않는다 — 출입증 쿠키를 함께 보내야 해서 아무 곳에나 열 수가 없다.


### 8.6 로그인과 출입증 검증
인터넷에서 닿을 수 있는 주소가 생겼으므로 나만 볼 수 있게 하는 장치가 필요하다. 쓰는 사람이 나 하나뿐이라 비밀번호 하나로 끝낸다.

**흐름**
1. 로그인 화면에 비밀번호를 넣는다.
2. 서버가 저장된 값과 대조해 맞으면 출입증(토큰)을 발급한다.
3. 이후 모든 조회 요청은 이 출입증을 함께 보내고, 서버가 매 요청마다 유효한지 확인한다. 없거나 만료됐으면 데이터를 한 줄도 주지 않는다.

**규칙**
- **비밀번호는 원문으로 저장하지 않는다.** 되돌릴 수 없게 변환한 값만 서버 `.env`에 둔다. DB에도 코드에도 넣지 않는다.
- **브라우저를 닫거나 12시간이 지나면 만료**된다. 둘 중 먼저 오는 쪽이다. 자동 연장은 두지 않는다.

  브라우저 종료만으로 끊지 않는 이유가 있다 — 크롬·사파리의 "마지막에 열어둔 탭 이어서 열기"는 세션 쿠키까지 복원해 버려서, 창을 닫았다는 사실이 만료의 근거가 못 된다. 그래서 만료 시각을 출입증 안에도 박아 두고 서버가 직접 거절한다.

  더 짧게 잡거나 아예 매번 받게 할 수도 있지만 그렇게 하지 않았다. 이 API는 조회 전용이라(8.1) 출입증을 훔친 사람도 주문을 낼 수 없고, 쿠키가 `HttpOnly`라 화면 코드로는 못 읽는다. 그러면 남는 탈취 경로는 내 기기를 이미 장악한 경우뿐인데, 그 사람은 화면을 그냥 보면 된다 — 유효기간을 12시간에서 1시간으로 줄여도 그 그림은 바뀌지 않는다. 짜증만 늘고 안전은 거의 그대로다.
- **연속 5회 실패하면 그 주소를 15분 잠근다.** 유효기간을 줄이는 것보다 이쪽이 실제 안전에 훨씬 크게 기여한다 — 출입증은 훔치기 어렵지만 로그인 문은 주소만 알면 누구나 두드릴 수 있고, 막지 않으면 하루에 백만 번쯤 찍힌다.

  세는 곳은 프로세스 메모리다(DB에 쓰지 않는 것이 8.1). 재시작하면 풀리지만 재시작을 일으키는 건 나뿐이라 문제가 안 된다. 대신 **API는 워커 하나로 띄워야 한다** — 여럿이면 워커마다 따로 세어 임계가 그만큼 느슨해진다.

  주소를 바꿔 가며 두드리면 이 잠금을 우회한다. 그건 이 계층에서 못 막고, 주소가 공개돼 있지 않다는 것(Tailscale Funnel이 주는 예측 불가능한 호스트명)과 scrypt가 시도당 수십 밀리초를 먹는다는 것이 남은 방어다.
- **출입증은 화면 코드가 읽을 수 없는 쿠키**에 담는다. 화면 쪽에 문제가 생겨도 출입증이 함께 새 나가지 않는다. Vercel이 `/api/*`를 넘겨 주므로(8.5) 이 쿠키는 화면과 같은 주소의 1차 쿠키가 되고, `SameSite=lax`로 충분하다. 화면에서 API를 직접 부르는 방식으로 바꾸면 그때는 `SameSite=none`이 필요하고 그 조건으로 `Secure`가 강제된다 — 즉 그 방식에서는 **전 구간 HTTPS가 아니면 로그인 자체가 성립하지 않는다.** `DASHBOARD_ALLOWED_ORIGINS`가 채워져 있으면 코드가 알아서 그쪽으로 넘어간다.
- **로그인 시도는 성공·실패 모두 기록**한다. 내가 하지 않은 시도가 보이면 그 자체가 신호다. 단 기록은 로그 파일에 남기고 DB에는 쓰지 않는다.
- 출입증 서명에 쓰는 열쇠도 `.env`에만 둔다. 열쇠를 바꾸면 발급된 출입증이 한꺼번에 무효가 되므로, 노출이 의심되면 그것이 곧 전체 차단 수단이다.

**두지 않는 것** — 아이디, 회원가입, 비밀번호 찾기, 2단계 인증, 권한 등급, 자동 로그인 유지. 쓰는 사람이 하나라 전부 불필요하다.
