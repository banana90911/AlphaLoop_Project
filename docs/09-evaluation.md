## 9. 성과 평가 · 백테스트

전략이 진짜 돈을 버는지 판정하는 기준과, 실제로 돌린 결과를 남긴다.

### 9.1 무엇으로 측정하나

**백테스트** — 과거 시세·수급으로 사이클 전체를 재생한다. 거래세·수수료·슬리피지·체결 현실을 반영하고, 룩어헤드(그때 알 수 없던 정보)와 생존편향(상폐 종목 누락)을 차단한다.

**벤치마크 4종**


| 벤치마크              | 무엇을 확인하나                         |
| ----------------- | -------------------------------- |
| 코스피 매수후보유         | 시장을 이기는가                         |
| 단순 모멘텀 (이동평균 크로스) | 공짜로 따라할 수 있는 규칙을 이기는가            |
| 무거래 현금            | 거래할 가치가 있는가                      |
| 균등가중 워치리스트 매수후보유  | 스크리너가 고른 40종목을 그냥 균등 보유한 것보다 나은가 |


**KPI** — 누적·연환산 수익률, 샤프·소르티노, MDD·고점회복기간, 승률·손익비·Profit Factor, 회전율, 벤치마크 대비 초과수익.

- **세전** — 거래세·수수료·슬리피지 차감
- **세후** — 양도세·배당세까지 차감. **게이트는 세후를 본다**



### 9.2 Go/No-Go 게이트

**하드 3조건**

1. 벤치마크 4종 전부 초과
2. PBO < 50% — 성적이 운일 확률
3. 파라미터 ±20%에서 절벽 없음 + 거래비용 2배에서도 벤치마크 초과



### 9.3 과최적화 방지

- 데이터를 시간순으로 튜닝 구간 / 검증 구간으로 나누고 검증 성과만 게이트에 쓴다
- 조정 가능한 파라미터는 7개 이하로 고정한다.

#### 9.5.1 선검증 (2026-06-09~10)

- **한 것** — 착수 전에 전제가 성립하는지부터 실측. API 발급, 후보 호스트에서 KIS 호출, 과거 데이터 수신, 주문유형 지원 확인.
- **결과** — GitHub Actions(해외 IP)는 KIS가 차단(토큰 발급 타임아웃), NCP 서울 서버는 HTTP 200. 일봉 12년·공매도 과거 수신 OK, 수급은 KIS가 30거래일만 제공. 스톱지정가는 모의 미지원.
- **결정** — 한국 IP 상시 호스트를 전제로 확정. 과거 수급·상폐 시세는 네이버 금융으로 보완(무료 출처만으로 통과). 손절 검증은 소액 실거래로 이월.



#### 9.5.2 KIS 모의 연동 (2026-06-11)

- **한 것** — `broker/kis_client.py` 작성 후 모의 계좌로 실측.
- **결과** — 잔고·현재가·일봉·수급 30일·공매도 26일 통과. 모의 도메인도 시세 4종 제공. 실주문 송출(장중 필요)과 스톱지정가는 미검증.
- **결정** — 시세는 모드별 도메인으로 통일(코드 분기 없음). 토큰은 파일 캐싱(발급 1분 1회 제한 회피), 조회는 5xx 백오프·주문은 재시도 금지.



#### 9.5.3 백테스트 워크포워드 1~5차 (2026-06)

- **한 것** — 전종목 2,537개, 2021-01-04~2026-06-12(1,333 거래일), 자본 1,000만원. 튜닝 252거래일 / 검증 63거래일 17구간으로 파라미터를 고르고 검증 성과만 집계.
- **결과** — 아래 표. 벤치마크(균등가중) = +8.9%(1~4차 구간).
- **결정** — 하락장 방어(지수 추세 필터) 채택. grid 확장은 한계로 판단하고 중단.


| 차수  | 핵심 변경                | 손잡이 | OOS 누적수익 | 샤프    | MDD    | PBO | DSR   |
| --- | -------------------- | --- | -------- | ----- | ------ | --- | ----- |
| 1차  | grid 36조합            | 4   | −19.6%   | −0.04 | −52.8% | 43% | (버그)  |
| 2차  | grid 144조합           | 6   | +14.2%   | 0.25  | −48.7% | 64% | (버그)  |
| 3차  | 하락장 방어 추가            | 6   | +42.5%   | 0.50  | −41.1% | 43% | (버그)  |
| 4차  | 3차와 전략 동일, DSR 버그 정정 | 6   | +42.5%   | 0.50  | −41.1% | 43% | 36.2% |
| 5차  | 전종목 11시간 실행          | 6   | +74.2%   | 0.84  | −21.0% | 54% | 74.0% |


**차수별로 무엇을 배웠나**


| 차수  | 배운 것                                                                                         |
| --- | -------------------------------------------------------------------------------------------- |
| 1차  | 추천값이 grid 경계에 몰림 → 탐색 범위가 최적점을 못 감쌌다                                                         |
| 2차  | 범위를 넓히고 손잡이를 늘리니 수익은 올랐지만 PBO 43→64% 악화. 손잡이↑ = 과최적화↑가 그대로 나왔다                               |
| 3차  | MDD는 튜닝으로 안 풀리는 구조적 문제(하락장 방어 부재)였다. 지수 추세 필터로 해결 — 값을 고정해 손잡이를 늘리지 않았다                      |
| 4차  | DSR이 항상 0이던 건 버그였다(시도들의 샤프 표준편차가 0이 되자 임의값 0.5를 하드코딩). 정정 후 36.2% — 낮은 값의 원인은 버그가 아니라 전략의 약점 |
| 5차  | OOS +74.2%지만 **벤치마크 미달**(같은 기간 코스피 +265%)·PBO 54%로 NO-GO. 원인 규명은 9.5.5                       |


데이터 자체는 정확했다. 2025~2026 강세장은 실제이고(코스피 실측·교차확인), 실오류는 상하한가를 넘는 일일 점프 25건뿐이다(기업행위 미조정, 300만 데이터점 중).



#### 9.5.4 게이트 재정의 (2026-06-21)

- **한 것** — 4차에서 DSR만 계속 미달하자 임계 0.95의 적정성을 재검토.
- **결과** — 0.95는 헤지펀드(수십 년·수백 종목) 전제라 개인·5년 데이터엔 과도하고, ">0"은 무조건 통과라 무력. 둘 다 극단이었다.
- **결정** — DSR을 하드 게이트에서 빼고 하드 3축(벤치마크·PBO·견고성)으로 확정. DSR은 자본을 얼마나 천천히 늘릴지의 참고 지표로 강등(9.2). 같은 시점에 벤치마크 4종을 전부 게이트에 연결하고, 견고성 검사도 실측 구현으로 바꿨다.



#### 9.5.5 5차 사후 진단 · 기본값 동결 (2026-06-25)

- **한 것** — 5차 NO-GO의 원인을 나누기 위해, 같은 파라미터로 평가 방식만 바꿔가며 다시 돌렸다.
- **결과** — 미달의 대부분이 전략이 아니라 평가 방식 탓이었다.

```
연속 보유 전체기간     +364.7%   (코스피 매수후보유 +265% 초과)
→ 워크포워드 OOS      +154.6%   (−210%p)
→ 튜닝까지 거친 OOS    +74.2%   (−80%p)
```


| 손실     | 정체                                                                 |
| ------ | ------------------------------------------------------------------ |
| −210%p | **계측 결함** — OOS 평가가 63일마다 초기 자본·빈 포지션으로 새로 시작해 장기보유 모멘텀이 분기마다 토막났다 |
| −80%p  | **과최적화** — 1년 구간에서 144조합을 고른 결과가 손 안 댄 기본값보다 못했다(PBO 54%와 일치)      |


- **결정 ①** 그리드 튜닝 기각, 기본값 동결. 튜닝이 기본값보다 못한 조합을 고르므로 `config/risk_params.toml` 기본값을 확정 전략으로 고정한다.
- **결정 ②** 선정·청산 개선은 닫는다. 메가캡을 초입만 먹고 놓친 문제(SK하이닉스 +2,740%)를 세 갈래로 풀어봤지만 전부 역효과였다.


| 시도                        | 결과                     |
| ------------------------- | ---------------------- |
| 진입 임계 완화                  | 효과 0 (실제 제약은 보유 슬롯 경쟁) |
| 저변동성 항목 제거                | +364% → +91%           |
| 승자 달리기 (부분익절 끔 + 트레일 4.5) | +364% → +9%            |


이 전략의 수익은 "괴물 한 방"이 아니라 159거래의 작은 이익을 다수 확정한 것이고, 부분익절+트레일링이 그 장치다. 둘은 양립할 수 없으므로 메가캡 미포착은 수용 가능한 비용이다.

- **결정 ③** 게이트는 동결 기본값 연속 실행으로 판정한다. 튜닝을 폐기했으니 워크포워드로 파라미터를 고를 이유가 없다 — 검증 기간을 연속 보유로 1회 실행 + 견고성 + 벤치마크 4종으로 본다.

**결정 ③에 따른 실행 (2023-01~2026-06)** — 전략 +364.7%(샤프 1.54·MDD −33.5%)


| 조건        | 결과                                               |
| --------- | ------------------------------------------------ |
| ① 벤치마크 4종 | **초과** ✅ — 코스피 +265%·단순모멘텀 +157%·현금 0%·균등가중 +49% |
| ② PBO     | 그리드를 탐색하지 않으므로 판정 대상 아님                          |
| ③ 견고성     | **실패** ⛔ — 파라미터 ±20% 이웃 14개 중 9개가 절벽             |


절벽 기준은 `eval/gate.sensitivity_no_cliff(drop_tol=0.5)` — 이웃 값의 누적수익이 기본값의 50%(=+182%) 이상 유지되면 절벽 없음. 2026-06-21 게이트 재정의 때 코드에 넣은 값이라 이 실행보다 앞선다. 비용 2배는 +93.7%로 균등가중(+49%)을 넘어 통과.

+364.7%는 벤치마크를 다 이기지만 *특정 값이 특정 구간에 맞은 취약한 봉우리*다. 튜닝으로 견고한 지점을 찾는 것은 또 다른 과최적화라 하지 않는다. 2023~2026은 이미 충분히 들여다봐 사실상 표본 내가 됐으므로 백테스트로 짜낼 정보는 소진됐다 — 최종 판정은 소액 실자본으로 이관하고, DSR 36.2%를 반영해 시작 자본을 작게 잡는다.

#### 9.5.6 설계·코드 정렬과 최종 판정 (2026-08-18)

- **한 것** — 문서와 코드가 다른 규칙으로 돌고 있던 것을 찾아 맞추고, 청산·사이징 규칙 하나씩을 켜고 끄며 성과 기여를 분리한 뒤 게이트를 다시 판정했다.
- **결과** — 문서와 코드의 차이 넷이 드러났고, 그중 셋은 켜는 순간 성과가 무너졌다.


| 규칙         | 문서       | 코드       | 켜면                            |
| ---------- | -------- | -------- | ----------------------------- |
| 부분 익절 40%  | 없음(당시)   | 있음       | 끄면 **+364.7% → +15.7%**       |
| 시간청산 우선순위  | 트레일링보다 앞 | 트레일링보다 뒤 | 앞으로 옮기면 **+364.7% → +138.3%** |
| 종목당 한도 13% | 있음(20%)  | 백테스트 미적용 | 걸면 **+364.7% → +7.7%**        |
| 손절폭 하한 5%  | 있음       | 없음       | 걸면 **+364.7% → +75.2%**       |


- **결정** — 실측이 가리키는 구성을 정본으로 확정했다. 부분 익절 40%를 유지하고, 시간청산은 트레일링 뒤에 두며(오르는 중이면 면제), **종목당 한도와 손절폭 하한은 두지 않는다**(05-risk 5.1·06-sizing 6.1). 코드·config를 그 정본에 맞췄다 — `partial_frac=0.4` 추가, `per_name_hard_pct`·`sector_pct` 검사 제거.

**세 규칙이 왜 그렇게 크게 작용하나**

- **부분 익절** — 없으면 +1.5R에 닿은 승자가 본전으로 되돌아올 때 0이 된다. 40%를 덜어내면 +0.6R이 남는다. 청산 사유가 손절 85건·시간청산 18건인 전략에서 이 차이가 누적된다.
- **시간청산 순서** — 트레일링이 손절을 올릴 수 있는 동안에는 시간청산이 검사되지 않는다. 즉 *오르는 중이면 20일 규칙이 면제*된다. 앞으로 옮기면 느리게 오르는 승자를 잘라낸다(시간청산 24 → 27건, 그 3건이 226%p).
- **종목당 한도** — 이 전략의 수익은 소수 종목 집중에서 나온다. 한도를 걸면 같은 자본이 더 많은 종목으로 흩어져(거래 159 → 198건) 대박 종목의 기여가 사라진다. 13%든 20%든 결과는 같다(+7.7% vs +14.2%).

**한도를 뺀 대가 — 정직 고지**

한도가 없으면 사이징이 한 종목에 얼마를 배정하는지 실측했다(11,053건 진입).
