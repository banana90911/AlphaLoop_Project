## 8. 대시보드
시스템/자본 상태를 확인하는 도구

### 8.1 지켜야 할 경계
- 읽기 전용
- 로그인도 DB에 저장하지 않는다.
- 시스템은 대시보드의 존재를 모른다. 둘은 DB로만 만난다.

### 8.2 "최신 상태"의 정의
- 브라우저가 60초마다 API를 다시 호출해 화면을 갱신한다. 페이지 전체를 새로 그리지 않고 바뀐 값만 다시 그린다.
- 화면 상단에 마지막 업데이트 시간 표시

### 8.3 기술
① — 백엔드는 `FastAPI` + `uvicorn`
② — 프론트는 `React` + `Vite` + `Tailwind CSS`
③ — 화면과 서버는 따로 배포한다. 화면은 Vercel, API와 DB는 NCP 서버.

차트 라이브러리는 화면을 만들면서 고른다(recharts·ECharts·uPlot 등). 조건 하나만 못 박는다 — npm 의존성으로 번들에 포함하고, 실행 중에 외부에서 불러오지 않는다. 외부 요청 0이 원칙이다.
백엔드 계약(조회 + JSON)은 프론트가 무엇이든 바뀌지 않는다. 그래서 API를 먼저 만들고 화면을 나중에 갈아엎어도 백엔드는 그대로다.

### 8.4 화면 구성
네 영역을 한 페이지에 놓는다. 페이지 이동이나 탭 전환 없이 스크롤만으로 전부 본다.

- 값이 오르면 빨강, 내리면 파랑으로 통일한다.
- 보유 종목이 20개까지 늘어난다.

**① 나의 정보 — 잔고·보유 종목·평가손익**
- 계좌 현황 : 총자본, 예수금, 평가손익, 당일 손익률
- 평가손익 : `Positions.AveragePrice` vs 마지막 사이클이 본 가격(`CycleScores.LastPrice`). + 그 사이클 시각.
- 보유 종목은 한 줄에 한 종목 — 종목명, 수익률(+색깔), 아랫줄에 평단, 보유일수, 수량(`Positions`(`status='open'`)), 손절가.
- 보유가 20종목까지 가므로 기본은 상위 5줄만 펼쳐 두고 나머지는 "더보기"로 접는다.

**② 수익 그래프 — 시간순 누적 + 벤치마크**
- 자본곡선 : `Outcomes.NetProfitLoss`(비용 차감 후 실현손익)를 청산일 순으로 누적. 성과 판단은 이 선 하나로만 한다.
- 호버 툴팁 : 그 거래의 날짜, 종목, 실현손익, R 배수(`rMultiple`).
- 곡선 위에 매수·매도 시점을 점으로 찍는다(초록·빨강). 어느 구간의 상승이 어느 거래에서 나왔는지 눈으로 잇는 용도다.
- 벤치마크 겹쳐 그리기 : `MarketIndices`의 코스피·코스닥 + 균등가중 워치리스트. 우리 전략이 비용 떼고 이들을 이기는지 한눈에 본다.
- 기간 토글은 일, 월, 년, 전체.
- 확대 및 좌우로 스크롤 가능. 확대 시 보여지는 부분을 토대로 그래프 상단/하단에 맞춘다.

**③ 거래 리포트 — 목록 + 근거 펼침**
- 목록 : `Orders`·`Positions`·`Outcomes`를 시간순으로 한 행씩. 열은 날짜, 시각, 구분(매수/매도), 종목(+종목코드), 단가, 수량, 거래대금, 손절가, 상태(보유/청산). 날짜 필터와 전체/매수/매도 토글로 좁힌다.
- 거래대금은 매수면 음수(초록), 매도면 양수(빨강)로 부호를 붙여 현금이 어느 쪽으로 움직였는지 바로 읽히게 한다.
- 펼침 — 진입 근거: `Decisions`의 점수·적용 임계·손절가·R·목표 보유 수·수량·기대 엣지, `CycleScores`의 항목별 백분위(모멘텀·수급·거래대금 증가·저변동성)와 레짐.
- 펼침 — 게이트 결과: `RiskChecks`에서 어느 관문에 걸려 거부·축소됐는지.
- 펼침 — 청산 결과: `Outcomes`의 실현손익·보유일수·청산 사유(`exitReason`).
- 이 근거들은 전부 숫자라 행 크기가 작다. 압축·삭제 없이 영구 보존하므로 몇 년 전 거래도 근거가 그대로 남는다.

**④ 오류·정지 알림**
- `SafeStopEvents` — 발생 시각·원인·해제 여부. 비어 있는 `releasedDateTime`이 곧 "지금 정지 중"이다.
- `Cycles` — `failed`·`skipped` 사이클과 실패 단계.
- `IngestRuns` — 일일 배치 결과. `failed`·`partial`이면 그날 데이터가 낡았다는 뜻이라 눈에 띄게 표시한다.
- 행을 고르면 원인과 무엇을 확인하고 어떻게 해제하는지를 함께 보여준다. 잔고 불일치·데이터 오류는 사람 개입 해제가 필수다.
- 대시보드는 읽기 전용이라 해제 버튼을 누르는 곳이 아니다 — 무엇을 해야 하는지 알려주는 곳이다.


### 8.5 어디서 읽고 어떻게 접속하나
- 매매 cron·DB·대시보드 API가 같은 NCP 서버에서 돈다. 대시보드는 같은 DB를 `SELECT` 전용 계정으로 읽으므로, 매매 코어가 기록하는 중에도 읽기가 막히지 않는다.
- 화면은 Vercel에 있고, 화면이 보내는 조회 요청은 Tailscale Funnel을 지나 서버로 간다. 도메인을 사지 않고도 전 구간이 암호화된다.
- 어느 기기에서든 브라우저로 접속한다. 폰에서도 같은 화면을 본다. 접속 전에 따로 준비할 것이 없다.
- 주소를 아는 사람이 있어도 로그인 없이는 아무것도 보지 못한다.


### 8.6 로그인과 출입증 검증
인터넷에서 닿을 수 있는 주소가 생겼으므로 나만 볼 수 있게 하는 장치가 필요하다. 쓰는 사람이 나 하나뿐이라 비밀번호 하나로 끝낸다.

**흐름**
1. 로그인 화면에 비밀번호를 넣는다.
2. 서버가 저장된 값과 대조해 맞으면 출입증(토큰)을 발급한다.
3. 이후 모든 조회 요청은 이 출입증을 함께 보내고, 서버가 매 요청마다 유효한지 확인한다. 없거나 만료됐으면 데이터를 한 줄도 주지 않는다.

**규칙**
- **비밀번호는 원문으로 저장하지 않는다.** 되돌릴 수 없게 변환한 값만 서버 `.env`에 둔다. DB에도 코드에도 넣지 않는다.
- **출입증은 7일 뒤 만료**된다. 자동 연장은 두지 않는다 — 일주일에 한 번 다시 넣는 편이 단순하고, 새 나갔을 때 피해 기간도 짧다.
- **출입증은 화면 코드가 읽을 수 없는 쿠키**에 담는다. 화면 쪽에 문제가 생겨도 출입증이 함께 새 나가지 않는다.
- **로그인 시도는 성공·실패 모두 기록**한다. 내가 하지 않은 시도가 보이면 그 자체가 신호다. 단 기록은 로그 파일에 남기고 DB에는 쓰지 않는다.
- 출입증 서명에 쓰는 열쇠도 `.env`에만 둔다. 열쇠를 바꾸면 발급된 출입증이 한꺼번에 무효가 되므로, 노출이 의심되면 그것이 곧 전체 차단 수단이다.

**두지 않는 것** — 아이디, 회원가입, 비밀번호 찾기, 2단계 인증, 권한 등급. 쓰는 사람이 하나라 전부 불필요하다.
