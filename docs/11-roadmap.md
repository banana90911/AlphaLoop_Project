## 11. 구현 로드맵

> *무엇을 어떤 순서로 만들고, 각 단계를 무엇으로 합격 판정하는가*의 단일 소스다. 각 Phase는 **목표 / 할 일 / 게이트(다음 단계로 넘어가는 조건)**로 쓰고, 이미 진행된 것은 **현황**에 남긴다. 파일·폴더 구성은 3-3, 검증 절차는 9.4가 단일 소스다.
>
> **호스트 전제**: 선검증 결과 KIS가 해외 IP를 차단하므로 **한국 IP 상시 서버**(현 NCP 서울)가 전제다. 더 먼 목표는 자택 맥미니이며, 설계가 호스트 비의존이라 전환 비용은 작다.

### 11.0 진행 원칙

- **게이트 기반 진행** — 각 Phase는 명시된 기준을 통과해야 다음으로 넘어간다. 특히 실자본 투입 게이트는 미달 시 진행 차단이다.
- **선검증 우선** — "이게 안 되면 나머지가 무의미한" 전제(호스트 접속·데이터 가용성)를 본격 코딩 전에 실측한다. 늦게 발견하면 그동안 만든 게 헛수고다.
- **측정 없으면 실자본 없다** — 실거래는 백테스트 방향성 게이트 + 소액 실거래 합격증을 통과한 뒤에만. 모의 KPI는 *기능 합격*만 주고 전략 합격으로 쓰지 않는다(4.3).
- **결정론 먼저** — 리스크·사이징·청산(Phase 3)을 결정 로직(Phase 4)보다 먼저 완성한다. 제안이 나오기 전에 그것을 검증·집행할 바닥이 있어야 한다.
- **원칙은 먼저, 구현은 단계적** — 운영 신뢰성(10장)의 원칙은 처음부터 문서에 박혀 있어야 하고, 구현은 10.16 순서대로 나눠 넣는다.

### Phase 0 — 선검증 + 스캐폴딩 ✅

**목표**: ① 현 전제(호스트·데이터)로 이 프로젝트가 가능한지 코드 착수 전에 판명 ② 후속 Phase가 딛고 설 리포·설정·스키마·운영 바닥 깔기.

**선검증 (막히면 전제부터 재설계)**

- API 발급 — KIS 계좌·App Key·모의 신청, DART·FRED·알림 채널.
- **호스트 접속 게이트** — 후보 호스트에서 KIS 인증·잔고 조회를 실제 호출해 해외 IP 차단 여부 판명.
- **백테스트 데이터 가용성 게이트** — 과거 5~10년 일봉 + 투자자 수급 + 공매도 + *상폐 종목 포함*을 받을 수 있는가. 안 되면 워크포워드·생존편향 차단이 전부 불가.
- **스톱지정가 모의 지원 확인** — 손절 메커니즘을 모의에서 검증할 수 있는지.

**스캐폴딩**: 리포 구조, `config/`(리스크 파라미터·날짜별 세율·호출 한도), 시크릿 로딩 단일 진입점, **SQLite 스키마 생성**(7장 카탈로그). 운영 신뢰성 1차 — idempotency 상태 머신, WAL·연결 단일 진입점, 시크릿, 시간대 경계 함수, 모드 분기 금지 CI.

**게이트**: 데이터·빈 사이클 상태 머신이 단위 테스트를 통과.

**현황(2026-06)**: 완료. 결과는 9.5.1 — GitHub Actions 탈락, NCP 서울 서버 확정. 데이터는 무료 출처만으로 통과. 스톱지정가는 모의 미지원 확정.

### Phase 1 — KIS 연동 (모의) ✅

**목표**: 모의 환경에서 인증·조회·주문·기록의 왕복을 완성하고, KIS 운영 현실을 결정론 정책으로 흡수한다.

- 토큰 자동 갱신, 잔고·시세·미체결·체결 조회, 모의 주문 송출 — `broker/kis_client.py`.
- 호출 한도(초당 80%), 5xx 종류별 처리, **주문 송출 실패 시 재시도 금지 + 사이클 내 즉시 체결조회**(10.3).
- 모의↔실전 갭 측정 착수 — 같은 작은 주문의 체결가 기준선 기록.

**게이트**: 모의계좌로 인증 → 시세 → 주문 → 기록 1사이클이 끝까지 돈다.

**현황(2026-06)**: 완료(9.5.2). 미검증은 실주문 송출과 스톱지정가로, 소액 실거래로 이월.

### Phase 2 — 데이터 레이어 + 일일 배치 ◑

**목표**: 코드가 데이터를 수집·보정해 점수를 낼 수 있는 형태로 정돈한다.

- **장 시작 전 일일 배치** — `run_daily_ingest.py`: 종목 명부·상태(종목마스터) → 일봉·수급 → 기업행위(DART 정형 API) → 지수 → 전 종목 점수 산출. 결과를 `IngestRuns`에 남긴다(3-1).
- **후보 선별** — `data/screener.py`: 제외·거래현실성 필터 → 통과 집합 내 다섯 항목 백분위 가중합 → 상위 40 + 당일 급등 + 보유 전부.
- **운영 시세·수급** — `data/market_data.py`: 워치리스트 종목의 사이클 시점 현재가·호가·잠정 수급.
- **데이터 보정** — 수정주가(±30% 초과 점프 검출), 거래일·휴장 판정, 신선도 점검, 비용·세금 단일 모델, 출처 폴백.
- 글로벌·매크로(`global_macro.py`), 이벤트 캘린더(`calendar.py`) — 숫자 경로가 정해지면 붙인다(4장).

**게이트**: 배치가 전 종목을 정확히 적재하고, 신선도 검사와 vintage 정책이 작동(9.4 ③).

**현황(2026-06)**: 후보 선별·운영 시세 경로 구현 완료 — `screener.py`(백분위 가중)·`panel.py`(횡단면 패널, 백테스트와 같은 피처 계산 재사용)·`pipeline/screening.py`·`market_data.py`. 사이클 1단계에 연결됨. *미착수*: **일일 배치 진입점**(전 종목 조회를 사이클에서 분리하는 설계는 3-1에서 확정됨), DART 기업행위 어댑터, 거래일·신선도 판정, 글로벌·매크로, 이벤트 캘린더.

### Phase 3 — 리스크 엔진 · 사이징 · 청산 ✅

**목표**: 제안을 검증·집행할 결정론 바닥을 완성한다.

- **하드룰·서킷브레이커** — `risk/risk_engine.py`: 종목당 한도·총노출·일일 손실 −4%(당일 시작 자본 대비 MTM), 검사 순서와 충돌 처리, 재개·복구, 이상행동 임계, 한국시장 특화(점상·VI·단기과열).
- **사이징** — `risk/sizing.py`: 변동성 타깃팅이 주 엔진(1일차 작동) + 프랙셔널 켈리가 상한(표본이 쌓이면 자동 활성, 그 전엔 휴면). 최종 수량 = min(변동성 타깃, 켈리 천장, 하드 한도).
- **청산** — `exec/exits.py`: R을 진입 시점에 영구 고정, 우선순위(논지 무효 → 손절 → 본전 상향 → 트레일링 → 시간), 스톱 재동기화.
- 동시 보유 종목 수는 따로 정하지 않는다 — 사이징이 종목당 금액을 정하므로 종목 수는 나눗셈의 결과다(6.1).

**게이트**: 룰별 단위 테스트 + 켈리 활성/휴면 경계 테스트 통과.

**현황(2026-06)**: 구현 완료. 전부 결정론 순수 함수 + 단위 테스트. **소액 자본 보정(2026-06-22)**: 신규 주문 폭주 임계가 "자본 1천만원당 5건" 비례식이라 자본 100만원에선 0.5건으로 쪼그라들어 단일 진입도 정지시켰다 → `max(동시보유 상한, 비례식)`으로 변경. *미연결*: 실시간 시장 상태(VI·거래정지) 플래그 공급. **미결 트레이드오프**: 종목당 한도 × 1주 단위 탓에 *주가가 종목당 한도 금액을 넘는 종목은 진입 불가*다(자본 20만원이면 5만원 초과 종목 전부 탈락). 버그가 아니라 전략적 선택(분산 vs 종목당 비중↑ vs 저가주 한정)이라 백테스트로 확정한다.

### Phase 4 — 결정 · 집행 (사이클 6단계 조립) ◑

**목표**: 점수 임계 규칙으로 결정을 내고, 6단계 사이클을 끝까지 잇는다. 전부 코드다.

- **결정** — `pipeline/decision.py`: 갱신된 종합점수를 진입 임계·무효 임계와 비교해 신규 진입·보유 청산 제안을 만든다(3-2).
- **집행** — `exec/orders.py`: `clientOrderId` 부여·재시도 금지·모드별 주문 구분, **체결 즉시 손절 스톱 등록**(장간 갭 방치 방지).
- **기록** — `memory/journal.py`: `Decisions`·`Orders`·`Positions`·`Outcomes` 적재. 결정 의도를 송출 *전에* 적재해 주문이 어느 결정에서 나왔는지 남긴다.
- **사이클 조립** — `pipeline/trading_cycle.py`: 1~6단계 오케스트레이션 + 상태 머신.

**게이트**: 실주문 차단 플래그로 6단계 드라이런이 끝까지 돌고, 점수·임계·게이트 결과가 기대대로 나온다(9.4 ④).

**현황(2026-06)**: 배선 대부분 완료 — 1단계 워치리스트 → 3단계 결정 → 4단계 게이트(정지/스킵/신규차단/진행) + 사이징 + 이상행동 게이트 + 종목당 하드룰 → 5단계 집행(청산으로 자금 회수 → 신규 진입, 체결 시 손절 스톱 등록) → 6단계 기록(`Outcomes`까지). `broker` 미주입 시 드라이런을 유지해 테스트·백테스트가 안전하다. 종목→시장 매핑을 진입에 배선해 청산 비용·세율이 종목별 실제 시장 기준으로 계산된다. *미검증(라이브 송출 1회 필요)*: KIS 실응답 필드 파싱, 모의의 스톱지정가 지원 여부. *미연결*: 라이브 잔고 동기화(선행 게이트) — 지금은 내부 `Positions`를 진실로 보므로, KIS 자동 스톱과의 이중 주문 방지는 이 배선 후에 완성된다. 그 밖에 스톱 정정(트레일 상향), 미체결 스톱 에스컬레이션, 부분 체결 분할 적재가 후속.

### Phase 5 — 기록 · 통계 집계 ◑

**목표**: 성과 통계를 코드(SQL/numpy)로 닫는다. 사이징이 쓸 입력을 여기서 만든다.

- **켈리 입력 집계** — `Outcomes`에서 최근 100건 청산의 승률·손익비를 롤링으로 산출해 사이징에 넘긴다(6.1). 표본이 적을 땐 수축이 중립 쪽으로 끌어당기므로, 데이터가 적다고 로직을 끄지 않는다.
- **점수 구간별 성과** — `Outcomes.entryScoreBucket`·`entryRegime`으로 묶어 "어느 점수대·어느 레짐의 진입이 실제로 벌었나"를 집계한다. 진입 임계 조정의 근거이자 켈리 확률의 입력이다.
- **레짐별 성과 집계** — 위 두 집계가 곧 "닮은 국면에서 이 셋업이 어땠나"의 답이며, 사이징 켈리 확률로 직접 들어간다. 별도의 사례 인출 단계는 두지 않는다(3-1·2.4).

**게이트**: 집계가 원시 표에서 재현되고, 표본 부족 구간이 중립으로 처리되는지 단위 테스트로 확인.

**현황(2026-08)**: `memory/calibration.py`(수축·Wilson 신뢰구간·시간가중) 구현 완료, 단위 테스트 통과. *미연결*: 거래가 아직 안 쌓여 집계 결과가 비어 있다(백테스트 시드 또는 모의 운영으로 채워지며 활성화된다). *정리 대상*: `memory/retrieval.py`(인출 스코어러)는 사이클에서 기억 검색 단계를 없애면서 소비자가 사라졌다 — 호출처가 없고 5축 중 3축이 상수라, 켈리 입력 집계에 흡수된 상태다. 파일·테스트·`config` 가중 블록 제거는 후속. *범위 밖으로 정리*: 반사실(거부·무거래 가상손익) 표는 데이터 모델에서 제외했다 — 같은 질문은 백테스트를 다시 돌리는 것이 더 정확하다(7장).

### Phase 6 — 백테스트 · 게이트 ◑

**목표**: 전략이 비용·세금을 다 빼고도 단순 전략을 이기는지 과거로 증명한다.

- 과거 재생 엔진 — `backtest/engine.py`: 거래세·수수료·슬리피지·체결 현실, 룩어헤드·생존편향 차단.
- 벤치마크 4종 + KPI 두 겹(세전·세후) — `eval/metrics.py`. 게이트 3조건 — `eval/gate.py`.
- 통계 시드 — 과거 재생으로 `Outcomes`를 선채움해 켈리 승률·손익비 초기값을 만든다.

**게이트 (★실자본 경로의 1차 관문)**: 세후 기준 **벤치마크 4종 전부 초과 + PBO < 50% + 견고성(±20% 절벽 없음·비용 2배)**. 하나라도 미달이면 No-Go.

**현황(2026-06)**: 엔진·워크포워드·하락장 방어·지표·게이트 구현 완료. 5차까지 실행하고 사후 진단으로 **그리드 튜닝을 기각·기본값을 동결**했다(9.5.4). *남은 일*: 동결 기본값 연속 실행으로 3조건 게이트를 재판정(콜드스타트 윈도잉 제거가 선행), 생존편향(상폐 유니버스) 보강. 상세는 9.5.

### Phase 7 — 모의투자 *기능* 검증

**목표**: 전 파이프라인이 무인으로 *끝까지 도는지* 확인한다. **기능 합격증만** 발급한다.

- 스케줄러 연결(서버 cron), 일일 배치 + 하루 10회 사이클 무인 운영.
- 확인 대상: 파이프라인 흐름, 리스크 룰 동작, 잔고 정합성 게이트, 배치 신선도 검사, 토큰·호출 한도, heartbeat, 시간대, 로그 회전, SQLite 무결성.
- 운영 신뢰성 3·4차 — 모드 분기 금지 CI, 마이그레이션, 분기 점검 체크리스트 가동(10.16).

**게이트**: 기능 합격(통과/미통과 이진). 모의 KPI는 부풀려진 값이라 Go/No-Go에 직접 넣지 않는다.

---

### Phase 8 — 소액 실거래 *전략* 검증

**목표**: 모의가 *못 주는* 합격증을 실자본 극소액으로 측정한다.

- **전제**: Phase 6 게이트 통과 + Phase 7 기능 합격.
- 자본의 5~10%로 실거래 모드 1~3개월.
- 측정은 **체결 메커니즘 실측이 주**다 — 실제 슬리피지·미체결률·VI·상하한가 락업 실동작·스톱지정가 실작동·모의↔실전 갭. 수익 KPI는 표본이 작아(30~120건) *신뢰구간만* 보고 점추정으로 단정하지 않는다.
- 백테스트 구간이 사실상 표본 내이고 DSR이 36.2%이므로 **자본을 아주 작게, 천천히** 늘린다(9.5.5).

**게이트**: *전략 합격증* — 실측 체결 품질이 백테스트 가정과 크게 어긋나지 않고, 조용한 실패 알림이 실효한다.

---

### Phase 9 — 대시보드

**목표**: 매매와 분리된 읽기 전용 사후 확인·복기 도구(8장). Phase 6 이후 언제든 병행 가능하다.

- FastAPI 읽기 전용 JSON API(`dashboard/api.py`, GET 전용)를 먼저. 프론트(`dashboard/web/`)는 착수 시점에 결정한다 — React·바닐라 등 후보는 8.3, Streamlit만 제외.
- 4영역(나의 정보·수익곡선+벤치마크·거래 리포트 드릴다운·오류/정지 알림), 60초 폴링 갱신.
- 모의·소액·실거래 KPI를 나란히 비교하는 탭(모의가 실전 대비 얼마나 낙관적인지) + 마지막 성공 사이클과 현재 시각의 갭 경고.
- 접속은 사설 경로만(SSH 터널·Tailscale). 공개 노출 0.

**게이트**: 4영역이 SQLite 소스와 정확히 매핑되고, 읽기 전용 불변식 위반이 없다.

---

### Phase 10 — 본격 실거래 · 자본 램프업

**목표**: 검증된 전략에만, 검증된 비중으로, 단계적으로 자본을 늘린다.

- **진입 조건**: Phase 6 게이트 통과 + Phase 8 전략 합격증 + 모의↔실전 갭 반영 후 KPI가 절대 임계 충족(수치는 자금 확정 후 9.2에서 정한다).
- **램프업**: 한 번에 100%가 아니다 — 10%(=Phase 8) → 30% → 60% → 100%. 각 단계 1~2개월 운영 후 *KPI가 직전 단계 대비 악화되지 않은 경우에만* 다음 단계로. 악화되면 직전 비중으로 되돌리고 원인을 분석한다.
- 외부 이중 안전망: KIS 출금한도 0·일일 거래한도 설정·실시간 알림. 전환 후 첫 30일은 매일 수기 점검.

**게이트**: 각 단계가 직전 단계 대비 KPI 비악화. 유의미한 악화 시 자본 회수.

### 11.1 의존성 한눈에

```
Phase 0 [선검증 → 스캐폴딩]
   │  (호스트·데이터가 확정되어야 그 아래 전부 의미)
   ▼
Phase 1 [KIS 모의] → Phase 2 [데이터·일일 배치] → Phase 3 [리스크·사이징·청산]
                                                        │ (결정론 바닥 먼저)
                                                        ▼
                                                  Phase 4 [결정·집행·사이클 조립]
                                                        ▼
                                                  Phase 5 [기록·통계 집계]
                                                        ▼
                                                  Phase 6 [백테스트] ──★게이트 3조건★
                                                        ▼ (통과해야 실자본 경로)
                                                  Phase 7 [모의·기능 합격]
                                                        ▼
                                                  Phase 8 [소액 실거래·전략 합격]
                                                        ▼
                                                  Phase 10 [본격 실거래·램프업]

Phase 9 [대시보드] ─ Phase 6 이후 언제든(읽기 전용, 매매와 독립)
```

핵심 분기점은 둘이다 — **Phase 0 선검증**(전제가 성립하는가)과 **Phase 6 게이트**(전략이 진짜 버는가). 이 둘을 통과하지 못하면 그 아래는 의미가 없거나 실자본을 넣어선 안 된다.
