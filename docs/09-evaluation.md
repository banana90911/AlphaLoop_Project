## 9. 성과 평가 · 백테스트
전략이 진짜 돈을 버는지 판정하는 기준과, 실제로 돌린 결과를 남긴다.

### 9.1 무엇으로 측정하나
**백테스트** — 과거 시세·수급으로 사이클 전체를 재생한다. 거래세·수수료·슬리피지·체결 현실을 반영하고, 룩어헤드(그때 알 수 없던 정보)와 생존편향(상폐 종목 누락)을 차단한다.

**벤치마크 4종**

| 벤치마크              | 무엇을 확인하나                         |
| ----------------- | -------------------------------- |
| 코스피 매수후보유         | 시장을 이기는가                         |
| 단순 모멘텀 (이동평균 크로스) | 공짜로 따라할 수 있는 규칙을 이기는가            |
| 무거래 현금            | 거래할 가치가 있는가                      |
| 균등가중 워치리스트 매수후보유  | 스크리너가 고른 40종목을 그냥 균등 보유한 것보다 나은가 |

**KPI** — 누적·연환산 수익률, 샤프·소르티노, MDD·고점회복기간, 승률·손익비·Profit Factor, 회전율, 벤치마크 대비 초과수익.
- **세전** — 거래세·수수료·슬리피지 차감
- **세후** — 양도세·배당세까지 차감

**비율 지표는 전부 TWR(시간가중수익률) 기준이다.** 입출금이 있으면 총자산은 손익과 무관하게 뛰고 내리므로, 그걸 그대로 수익률로 쓰면 "입금을 많이 한 달"이 "잘 번 달"로 보인다. 금액 축과 비율 축을 분리해 각각 맞는 기준을 쓴다.

| 지표 | 기준 | 이체 영향 |
| - | - | - |
| 누적 실현손익(원) | `Outcomes.NetProfitLoss` 누적 | 없음 |
| 총자산(원) | `AccountSnapshots.TotalAsset` | 있음 — 대시보드에서 이체 마커로 설명 |
| **수익률·CAGR·MDD·샤프** | **TWR** | 제거됨 |

```
구간수익률 rᵢ = (기말자산 − 기초자산 − 순흐름) / (기초자산 + 순흐름)
TWR 지수 = Π(1 + rᵢ)
```

**MDD도 반드시 TWR 지수 위에서 계산한다.** 총자산으로 재면 출금이 가짜 낙폭을 만든다 — 자본의 30%를 빼면 그날 −30% 낙폭이 기록에 남는다. 벤치마크(코스피·코스닥) 비교도 TWR 기준이어야 공정하다. 어느 `CashFlows.Kind`를 흐름으로 빼고 어느 것을 수익으로 남기는지는 07-model의 `CashFlows` 절 표를 따른다 — 배당을 흐름으로 빼면 배당 수익이 통째로 사라진다.

**백테스트 성적표 숫자는 바뀌지 않는다.** 백테스트에는 이체가 없으므로 모든 구간의 순흐름이 0이고, 그러면 TWR은 단순수익률과 정확히 같아진다. 9.5의 수치를 다시 계산할 필요가 없고, 실거래와 백테스트를 같은 자로 비교하는 것도 그대로 성립한다.


### 9.2 Go/No-Go 게이트
**하드 3조건**
1. 벤치마크 4종 전부 초과
2. PBO < 50% — 성적이 운일 확률
3. 파라미터 ±20%에서 절벽 없음 + 거래비용 2배에서도 벤치마크 초과


### 9.3 과최적화 방지
- 데이터를 시간순으로 튜닝 구간 / 검증 구간으로 나누고 검증 성과만 게이트에 쓴다
- 조정 가능한 파라미터는 7개 이하로 고정한다.

#### 9.6.1 선검증 (2026-06-09~10)
- **한 것** — 착수 전에 전제가 성립하는지부터 실측. API 발급, 후보 호스트에서 KIS 호출, 과거 데이터 수신, 주문유형 지원 확인.
- **결과** — GitHub Actions(해외 IP)는 KIS가 차단(토큰 발급 타임아웃), NCP 서울 서버는 HTTP 200. 일봉 12년·공매도 과거 수신 OK, 수급은 KIS가 30거래일만 제공. 스톱지정가는 모의 미지원.
- **결정** — 한국 IP 상시 호스트를 전제로 확정. 과거 수급·상폐 시세는 네이버 금융으로 보완(무료 출처만으로 통과). 손절 검증은 소액 실거래로 이월.


#### 9.6.2 KIS 모의 연동 (2026-06-11)
- **한 것** — `broker/kis_client.py` 작성 후 모의 계좌로 실측.
- **결과** — 잔고·현재가·일봉·수급 30일·공매도 26일 통과. 모의 도메인도 시세 4종 제공. 실주문 송출(장중 필요)과 스톱지정가는 미검증.
- **결정** — 시세는 모드별 도메인으로 통일(코드 분기 없음). 토큰은 파일 캐싱(발급 1분 1회 제한 회피), 조회는 5xx 백오프·주문은 재시도 금지.


#### 9.6.3 백테스트 엔진 설계 대조 (2026-08-20)
- **한 것** — 사이클마다 같은 워치리스트를 다시 보는 것이 맞는지 점검하다가, 백테스트가 설계대로 돌고 있는지를 조항 단위로 대조했다.
- **결과** — 구 `backtest/engine.py`가 설계를 따르지 않았다. 설계 문서가 사이클 구조를 정한 뒤에 만들어졌는데도 일봉 1회 루프로 작성됐고, 이후 커밋이 그 위에 쌓였다. 이탈 14건 중 성과에 크게 작용한 것은 다음과 같다.

| 설계 | 구 엔진 |
| --- | --- |
| 워치리스트는 전일 종가 기준 | 당일 종가로 뽑아 당일 종가에 매수 |
| 하락장 필터를 두지 않는다(4장 지수 행) | 지수 추세 필터를 주입해 하락장 진입 차단 |
| 거래대금 증가 가중 0.15 | 컬럼명 불일치로 모든 종목에 상수 0.5 — 항목이 죽어 있었음 |
| 저변동성 60일 · 정배열 종가>20일선>60일선 | 20일 · MA5>MA20 조합 |
| 손절 스톱은 장중 체결 | 종가에서만 손절 판정 |
| 유동성 필터·총노출·켈리 | 전부 미적용 |

- **결정** — 설계를 그대로 재현한 `backtest/spec_engine.py`를 정본으로 세우고, 구 엔진 기반의 이전 실행 이력은 폐기했다. 재발 방지로 피처·제외 필터·점수식을 `data/features.py`·`data/screener.py` 한 곳에 모아 운영과 백테스트가 같은 코드를 쓰게 했다 — 두 쪽이 각자 정의를 들고 있던 것이 사고의 원인이었다. 이 통합 과정에서 수급 항목을 백분위로 바꾼 뒤 한 번 더 백분위를 매기던 오류도 함께 잡혔다.


#### 9.6.4 층위별 분해 진단 (2026-08-20)
- **한 것** — 전종목 2,537개, 2023-01-04~2026-06-12, 자본 1,000만원. 성과가 어느 층위에서 새는지 보려고 신호·집중도·사이징·청산을 층위별로 나눠 쟀다. 신호는 손절·비용·슬롯을 모두 뺀 상태에서 점수 분위별 다음날 수익률로 쟀다.
  > 아래 수치는 **다섯 항목(정배열 포함)·변동성 타깃팅 시점**의 값이다. 항목 구성은 넷으로 바뀌었으므로 현재 성적은 9.5를 본다.
- **결과**

| 층위 | 발견 |
| --- | --- |
| 스크리너 신호 | **정상** — 점수 10분위가 단조 증가(최하위 −37.1%, 9분위 +88.6%, 최상위 +173.8%/샤프 1.18) |
| 포지션 집중도 | **최대 결함** — 상위 5종목만 담으면 신호가 가장 좋은데도 +43.3%에 낙폭 −60.1%. 20종목이면 +227.5%에 −33.4% |
| 사이징 | 변동성 타깃팅이 자본을 앞선 종목에 몰아줘, 슬롯을 늘려도 실제 보유가 6종목에서 멈춤 |
| 켈리 | `f≤0 → 수량 0` 해석이 상한이 아니라 매매 중단 스위치로 작동 — 839일 중 572일 신규 차단, 자본 86%가 현금으로 놀았다 |
| 청산 | 부분 익절이 승률만 올리고 누적 수익을 깎음 |
| 진입 시각 | 14:30 +227.5%(샤프 1.24) vs 개장 직후 +85.5%(0.70) — 개장 직후는 밤사이 갭 노이즈를 그대로 맞는다 |

  **켈리는 상한이 아니라 스위치로 작동하고 있었다.** `f≤0 → 수량 0` 해석을 세 가지로 바꿔 재면(5종목·변동성 타깃팅 기준):

| 켈리 처리 | 누적 | 샤프 | MDD | 평균 현금 |
| --- | --- | --- | --- | --- |
| 미사용(휴면 고정) | +128.6% | 0.88 | −47.3% | 22.4% |
| 현행 `f≤0 → 0` | +9.6% | 0.27 | −21.0% | **82.2%** |
| `f>0`일 때만 상한 | +76.0% | 0.94 | −21.0% | 61.9% |

  **오래 들고 갈수록 좋다.** 상위 5종목을 손절 없이 N거래일 유지했을 때(무비용): 1일 +0.3%(샤프 0.22) · 5일 +48.2%(0.49) · 20일 +86.3%(0.68) · **60일 +217.1%(1.06)**. 청산 규칙이 추세를 너무 일찍 자르고 있다는 신호다.

  벤치마크도 다시 봐야 한다. 같은 기간 코스피 지수는 +265%지만 필터를 통과한 종목의 동일가중 평균은 +45.3%다. 지수를 끌어올린 것은 대형주 쏠림이고, 동일가중 전략이 구조적으로 따라갈 수 없는 부분이다.

  **자본 규모는 20종목 구성을 막지 않는다.** 필터 통과 종목의 주가 중앙값이 1만 6천원이라, 자본 100만원(종목당 5만원)에서도 후보의 78.6%를 살 수 있고 실제 평균 보유가 19.8종목이었다. 다만 자본이 작을수록 정수주로 잘려 배분이 의도에서 어긋난다 — 100만 +208.3%(샤프 1.22) · 300만 +159.6%(1.05) · 1,000만 +238.9%(1.28)로 편차가 크다.

- **결정** — 사이징을 동일가중으로 바꾸고 목표 보유를 20종목으로, 켈리는 상한으로 작동할 때만 씌우고, 부분 익절을 없앴다. 정기 사이클은 14:30 하루 1회로 모으고 그 사이는 보유 감시만 둔다.


#### 9.6.5 워크포워드 OOS 검증 (2026-08-20)
- **한 것** — 위 값들을 전 구간 성적을 보고 골랐으므로, 고를 때 보지 않은 구간에서 다시 쟀다. 학습 250거래일에서만 파라미터를 고르고 다음 125거래일에 적용하는 방식으로 6구간(`run_walkforward.py`). 구간마다 자본을 초기화하지 않고 자본·보유는 이어가며 파라미터만 갈아끼운다 — 그 초기화가 장기보유 모멘텀을 토막내는 계측 결함이기 때문이다.
- **결과** — OOS 구간 2023-01-06~2026-02-03.

| | 누적 | 샤프 | MDD |
| --- | --- | --- | --- |
| ① WF 튜닝(구간마다 재선택) | +187.4% | 1.36 | −27.1% |
| ② 고정 기본값 | +206.1% | 1.43 | −32.5% |
| ③ 고정 공격형(트레일 4.0·시간청산 없음·손절 3.0) | +305.8% | 1.78 | −27.3% |
| 코스피 매수후보유 | +130.9% | 1.52 | −20.7% |

- **결정**
  - **그리드 튜닝 기각.** 구간마다 최적값을 다시 고른 ①이 그냥 고정한 ②보다 못하다. 파라미터는 동결하고 게이트는 고정값 연속 실행으로 판정한다.
  - **고정 기본값을 확정 전략으로 둔다.** OOS 누적이 코스피를 앞서고 샤프는 근소하게 못 미친다(1.43 vs 1.52).
  - **목표 종목 수 20 유지.** 5는 확실히 배제되고, 10·20·25는 누적이 +227~250%로 붙어 있어 그 안에서 값을 고르는 것은 노이즈다. 다만 낙폭이 종목 수에 반비례해(10종목 −44.7% → 20종목 −33.4%) 20을 택한다.
  - **③은 채택하지 않는다.** 그 조합은 전 구간을 보고 골랐고 OOS 구간이 그와 겹쳐 진짜 표본 밖이 아니다. 학습 구간별 선택에서도 `trail_k`가 4:2로 갈렸다. 새 구간이 쌓인 뒤 다시 본다.
  - **청산 규칙은 하나씩 끄고 재서 골랐다.** 20종목 동일가중 기준(네 항목 확정 후 재측정):

| 청산 설정 | 누적 | 샤프 | MDD |
| --- | --- | --- | --- |
| 현행(부분익절 없음) | +227.5% | 1.24 | −33.4% |
| 부분익절 0.4로 되돌림 | +204.0% | 1.28 | −26.7% |
| 시간청산 끔 | +220.2% | 1.22 | −31.0% |
| 공격형(트레일 4.0·시간청산 없음·손절 3.0) | +408.4% | 1.62 | −26.1% |

**시간청산은 유지한다.** 끄면 제자리걸음 종목이 슬롯을 점유해 새 진입 기회를 막는다. 다섯 항목 시점의 단독 측정에서는 끄는 쪽이 −70%p로 크게 나빴다.

  - **부분익절 제거는 우세하나 만장일치는 아니다.** 6개 학습 구간 중 4개가 제거를 골랐고 고정 비교에서도 누적이 +23.5%p 높다. 다만 샤프(1.24 vs 1.28)와 낙폭(−33.4% vs −26.7%)은 부분익절을 두는 쪽이 근소하게 낫다. 누적과 설계 원리를 따라 제거를 유지한다.



#### 9.6.6 스크리너 항목 검정과 구성 확정 (2026-08-20)
- **한 것** — 가중치에 "타당한 근거 필요" 표시가 남아 있었다. 값을 그리드로 고르는 것은 이미 두 번 기각됐으므로, 대신 각 항목이 설계가 말한 방향대로 미래수익을 맞히는지만 검정했다. 그다음 항목 구성 후보를 학습 2022~2023(하락장, 코스피 −11.2%)에서 고르고 검증 2024~2026(강세장, +204.3%)에서 확인했다.
- **결과 ① 항목별 예측력** (20거래일 앞 수익률 기준)

| 항목 | mean IC | IC IR | hit | 연도별 부호 |
| --- | --- | --- | --- | --- |
| 저변동성 | **+0.165** | **1.32** | 90.6% | 5년 전부 양수 |
| 모멘텀 (12-1) | +0.037 | 0.34 | 63.9% | 2022만 −0.001, 이후 양수 |

저변동성이 사실상 엔진이다. 다른 항목을 다 합친 것보다 예측력이 크고, 모멘텀과 상관 −0.24로 04-data가 말한 "직교 축"이 데이터로 확인된다. 반면 모멘텀은 상위 40종목 안에서만 보면 부호가 뒤집힌다(+0.028 → −0.020) — 전형적인 모멘텀 크래시이고, 저변동성을 섞은 이유가 여기 있다.

- **결과 ② 구성별 성과** (14:30 · 20종목 동일가중)

| 구성 | 학습 누적 | 학습 샤프 | 검증 누적 | 검증 샤프 |
| --- | --- | --- | --- | --- |
| 현행 5항목 | −9.8% | −0.07 | +75.4% | 0.87 |
| 정배열 제외 | −6.2% | 0.00 | +132.2% | 1.24 |
| **정배열·수급5일 제외** | **+20.4%** | **0.50** | +177.0% | 1.49 |
| 현행 + 공격형 청산 | −4.9% | 0.01 | +225.0% | 1.56 |

- **결정**
  - **정배열을 뺀다.** 하락장·강세장 양쪽에서 일관되게 개선한 유일한 단독 변경이다.
  - **수급은 20일만 쓴다.** 5일은 20일에 이미 포함된 구간이라 최근 5일에 이중 가중을 주는 셈이었는데, 그 강조가 예측력을 더하지 못했다.
  - **거래대금 증가는 IC가 음수여도 유지한다.** 빼면 성과가 반토막 난다(+227.5% → +119.0%). 단변량 IC와 포트폴리오 기여는 다르다는 것을 이 항목이 보여준다 — 항목을 IC만으로 잘라내면 안 된다.
  - **공격형 청산은 채택하지 않는다.** 검증 구간 성적은 가장 좋지만 학습 구간(하락장)에서 방어를 못 했다. 강세장 전용 설정으로 판단한다.
  - **가중치는 탐색하지 않는다.** 남은 네 항목의 비중은 원래 값(0.35 / 0.25 / 0.15 / 0.15)을 그대로 두고 합 0.90을 1.0으로 재정규화한다. 항목을 뺐다고 남은 값을 손보면 그 조정이 곧 근거 없는 선택이 된다.
  - 확정 구성의 성적은 학습 +20.4%(샤프 0.50)·검증 +177.0%(1.49)다. **하락장에서 플러스를 낸 유일한 구성**이지만 검증 구간 샤프는 코스피(1.72)에 못 미친다.

- **한계** — 후보 6개 중에서 골랐으므로 선택 편의가 완전히 없지는 않다. 다만 학습/검증을 시간으로 나눴고, 검증 결과를 보고 후보를 다시 만들지 않았으며, 두 구간이 서로 다른 국면(하락장/강세장)이라는 점이 이 검정의 근거다.


#### 9.6.7 서킷브레이커 기준선 정의 불일치 해소 (2026-09-02)

설계 문서와 백테스트 구현이 갈라져 있던 것을 발견하고 문서를 백테스트 쪽으로 맞췄다.

- **불일치**: `AccountSnapshots.DayStartAsset`은 "당일 첫 사이클의 총자본"으로 정의돼 있었다. 정기 사이클은 하루 한 번이므로 이 정의대로면 분모와 분자가 같은 값이라 `DayReturnPercent`가 **항상 0%**가 되고, 실거래에서 −4% 서킷브레이커가 영원히 발동하지 않는다. 반면 백테스트(`spec_engine`)는 처음부터 **전일 종가 기준 총자산**을 기준선으로 쓰고 있었다.
- **해소**: 컬럼을 `BaseAsset`으로 개명하고 의미를 "직전 거래일 마지막 스냅샷의 `TotalAsset`"으로 못박았다. 백테스트 로직은 손대지 않았으므로 9.5 성적은 그대로다. 10-ops 10.9(동일성 매트릭스)가 막으려던 종류의 사고였다.
- **실측 발동률** — `tune_results/walkforward_oos.json`의 `diag.cycle_blocked / diag.cycles` (OOS 2023-01-06 ~ 2026-02-03):

  | 런 | 차단 / 전체 | 비율 |
  | - | - | - |
  | ① WF 튜닝(구간마다 재선택) | 14 / 750 | 1.87% |
  | ② 고정 기본값(현재 확정) | 14 / 750 | 1.87% |
  | ③ 고정 공격형 | 15 / 750 | 2.00% |

  1~2% 구간이라 브레이커는 잠자는 안전장치로 동작하고 있고 수익 영향은 무시할 수 있다. `daily_loss_pct = 0.04`를 조일 이유도 풀 이유도 지금은 없다.
