# 한국 주식 자동매매 플랫폼

> 상태: **설계 확정 + 부분 구현** · 개인용 1인 프로젝트

한국 주식(코스피·코스닥 보통주)을 대상으로 **모멘텀 + 수급 스윙 전략**을 자동으로 집행하고, 그 결과를 대시보드로 확인하는 개인용 시스템이다. 사용자는 직접 매매하지 않는다.

목표는 *자동으로, 안전하게 최대한의 수익을 내는 것* — **수익이 목표이고, 파산 방지는 그 수익을 끝까지 추구하기 위한 제약**이다.

**초기 구축 단계는 AI(LLM)를 쓰지 않는다.** 후보 선별부터 결정·사이징·집행까지 전 단계를 코드(통계·규칙)가 수행한다. 운영·백테스트 기록이 쌓인 뒤 *어느 단계가 코드로 한계에 부딪히는지*가 데이터로 드러날 때, 그 지점에 한해 AI 도입 여부를 따로 판단한다.

## 무엇을 하는가

- **자동 매매**: 평일 장중 10:00~14:30에 30분 간격으로 사이클이 돌며(하루 10회) 매수·청산·보유를 판정한다. 장 시작 전에는 전 종목 데이터를 준비하는 배치가 하루 한 번 돈다.
- **리스크 통제**: 손절·트레일링·종목당 한도·총노출·일일 손실 한도를 코드가 강제한다. 손절은 KIS에 스톱지정가로 미리 등록해, 시스템이 꺼져 있는 동안에도 자동 체결된다.
- **성과 측정**: 거래세·수수료·슬리피지·세금을 뺀 뒤 코스피 매수후보유 등 벤치마크 4종과 비교한다.
- **대시보드**: 같은 DB를 조회 전용으로 열어 수익·포지션·결정 근거·정지 이력을 보여준다. 비밀번호로 로그인한 뒤 어느 기기에서든 본다.

## 핵심 설계 원칙

1. **결정은 결정론적 코드가 한다.** 같은 입력이면 항상 같은 결정이 나오고, 백테스트와 실거래가 같은 코드 경로를 쓴다.
2. **모델보다 데이터·워크플로우가 핵심이다.** 어떤 데이터를 어떻게 정제해 어떤 규칙에 넣고, 어떻게 검증·집행하느냐가 이 시스템의 가치다.
3. **프레임워크 없이 직접 조립한다.** 단일 목적 라이브러리만 쓰고, 지표·백테스트·게이트를 직접 구현한다. 추상화가 얇을수록 무엇을 왜 했는지가 그대로 남는다.
4. **사이징·청산이 방향만큼 수익을 좌우한다.** 종목을 맞히는 것은 절반이고, 얼마를 사고 언제 파느냐가 나머지 절반이다.
5. **측정이 없으면 수익도 없다.** 단순 전략을 비용 떼고도 이겨야 가치가 있다. 모의 → 소액 실거래 순으로 검증한 뒤에만 자본을 늘린다.

## 한 사이클의 흐름 (6단계)

1. **후보 선별** — 전 종목에서 매매 부적합을 걸러내고, 점수 상위 40 + 당일 급등 + 보유 전부를 워치리스트로 묶는다
2. **데이터 수집** — 워치리스트의 현재가·호가·잠정 수급, 글로벌·매크로
3. **결정** — 실시간 데이터로 종합점수를 갱신해 진입 임계·무효 임계로 판정하고, 사이징이 수량을 환산한다
4. **리스크 검증** — 잔고 정합성 → 시장 상태 → 데이터 신선도 → 서킷브레이커 → 하드룰 → 종목 상태
5. **주문 실행** — KIS 주문 송출 + 체결 즉시 손절 스톱 등록
6. **기록** — 점수·결정 근거·게이트 결과·체결을 전부 DB에 남긴다

과거 성과는 별도의 "기억 검색" 단계가 아니라, 레짐별 승률·손익비 집계로 사이징(3단계)에 직접 들어간다.

## 기술 스택

| 영역 | 선택 |
| --- | --- |
| 언어 | Python 3.12 |
| 증권사·시세 | 한국투자증권 KIS Developers API |
| 글로벌·매크로 | `yfinance`, FRED |
| 기업행위 공시 | DART 정형 API |
| 데이터 처리·지표 | `pandas`, `numpy`, `exchange_calendars` |
| 게이트 통계 | `scipy` (PBO·Deflated Sharpe) |
| 스키마·설정 | `pydantic` v2, `pydantic-settings`, `tomllib` |
| 저장소 | `PostgreSQL` — 매매 코어와 같은 서버, 모든 프로세스의 유일한 공유점 (쓰기·조회 계정 분리) |
| 대시보드 | `FastAPI` 조회 전용 JSON API + `React`·`Vite`·`Tailwind CSS` (비밀번호 로그인 — 08-dashboard 8.6) |
| 배포 | 매매·DB·API는 NCP 서울 서버, 화면은 Vercel, 둘을 잇는 길은 Tailscale Funnel (10-operations 10.13) |
| 로깅·테스트 | `structlog`, `pytest`, `ruff`, `mypy` |

모의투자와 실전 투자는 설정값(도메인·계좌번호)만 다르고 코드는 동일하게 동작한다 — 코드에 모드 분기를 두지 않는 것이 불변식이며 CI가 이를 강제한다.
