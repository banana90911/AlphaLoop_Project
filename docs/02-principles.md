## 2. 핵심 설계 원칙

*현재 단계에서는 LLM 미사용



### 2.1 LLM은 제안하고, 결정론적 코드가 집행한다

> 모든 판단을 LLM에게 주는 것이 아닌 사전 정의된 기준을 거쳐 LLM의 판단을 검증하고 보강한다.
> LLM 출력은 제안 주문일 뿐이다. 코드의 하드 리스크 검증을 통과해야만 실제 주문이 나간다.

지표 계산·손익 계산·리스크 검증·서킷브레이커·주문 집행은 **전부 LLM이 아닌 코드**가 한다.



### 2.2 프로젝트의 핵심은 모델이 아닌 데이터·워크플로우이다

> LLM 외 주가에 영향을 미치는 다양한 데이터를 사용하여 컨텍스트를 확보한다. 
> 데이터를 정제하고 최적의 워크플로우를 설계하여 환각을 줄인다.

모델 추론력은 교체 가능한 상품이다. 이 프로젝트의 가치·해자는 **① 어떤 데이터를 ② 어떻게 구조화·압축해 ③ 어떤 에이전트에 라우팅하고 ④ 결정론적 코드로 어떻게 집행하느냐**에 있다. 
데이터 없는 전문가 에이전트는 환각 생성기이므로, 확보 가능한 데이터에만 전문가를 붙인다.

코드는 숫자, LLM은 글: LLM은 코드가 못 하는 일에만 사용한다. 코드가 못 하는 일은 단 하나, 글(자연어)을 읽고 의미·맥락을 판단·생성하는 것이다. 지표·수급·매크로·섹터강도·레짐 같은 숫자 신호는 코드가 계산하므로, 그 숫자를 말로 다시 설명하는 LLM 분석가는 토큰·환각만 더하고 새 정보가 없다.

자본 규모가 LLM 사용 범위를 정한다: 이 프로젝트의 실제 투입 자본은 검증 10~30만원·본격 ~100만원 규모다. 이 규모에선 LLM 월 고정비가 수익률을 직접 깎는다. 따라서 에이전트 수는 다다익선이 아니라 자본 대비 비용이 수익을 잠식하지 않는 선에서 정해지며, 각 LLM은 비용을 떼고도 코드만 한 버전을 이긴다는 백테스트 증명을 통과해야만 존속한다.



### 2.3 코드 기반 파이프라인 (프레임워크 미사용)

> 매매에선 "방금 LLM에 무엇을 보냈고 무엇을 받았나"가 1차 자료이다. 매매 로깅이 가능하도록 투명성을 확보한다.

LangChain·LangGraph·LlamaIndex 같은 LLM 오케스트레이션 프레임워크를 사용하지 않는다. 그 이유는 다음과 같다.

- 단순한 흐름
- 투명성 보장
- 추적 가능성
- 디버깅
- 프레임워크 의존성 안정성

왜 Claude(Anthropic SDK)인가 

정직하게, "Claude여야만 한다"는 검증된 근거는 없다 — 세 모델 모두 프롬프트 캐싱·구조화 JSON·도구 사용·롱컨텍스트·async SDK를 갖췄고 프론티어 동급이다. Claude를 고른 것은 ① 이 작업의 요건(한국어 공시·뉴스 독해, "제안만·결정은 코드" 규율의 지시 준수, 반복 시스템 프롬프트의 캐싱 비용 절감)에서 약점이 없고 ② 단일 공급자 + 1:1 SDK라는 감사 설계와 잘 맞기 때문이지, 다른 모델로는 불가능해서가 아니다.

### 2.4 학습 = 폐루프 메모리 학습

> 시스템은 같은 실수를 반복하지 않고, 과거 데이터를 활용하여 더 나은 선택을 한다.

Fine-tuning과 같은 LLM 모델 자체를 학습시키는 방법도 있으나 해당 프로젝트에서는 이처럼 가중치를 학습하지 않는다. 현실적·효과적 학습은 **결정 → 실제손익 → 데이터 적재 → 다음 결정 컨텍스트 주입**의 in-context 피드백 루프이다 . (강화학습·가격예측 모델 등 진짜 ML은 핵심 밖, 추후 옵션.)

**과거를 꺼내 쓰는 방식은 사례 인출이 아니라 통계 집계다.** 노트를 잘 채워도(학습) 맞는 페이지를 못 펴면 학습은 무쓸모이므로, 무엇을 어떻게 꺼내는지는 학습과 동급으로 설계해야 한다. 다만 꺼낸 것을 읽고 판단할 주체가 코드뿐이라면, 닮은 사례 몇 건을 골라 요약해 봐야 코드가 소비할 수 있는 형태가 아니다. 그래서 **레짐×셋업 칸별로 과거 결정과 실제 손익을 집계한 승률·손익비**를 꺼내 사이징의 켈리 확률에 직접 넣는다(3-2·6.1). 표본이 적은 칸은 수축이 중립 쪽으로 끌어당긴다.

이 결정에 따라 사이클에는 "기억 검색" 단계를 따로 두지 않는다 — 집계는 결정·사이징의 입력이지 그 앞의 독립 공정이 아니다.

임베딩/RAG는 의도적 범위 제외 — 기억은 자가생성 정형 데이터라 구조화 집계가 더 정밀하고, 소표본에서 의미검색은 "말만 닮은" 정보를 확신하며 끌어오는 오인출 위험이 크다. 



### 2.5 현실적 기대치

> 더 나은 예측을 위해 그에 상응하는 데이터를 사용한다.

시스템/LLM 재량매매가 시장을 이긴다는 검증된 근거는 없으며 실제 손실 위험이 있다. 이 프로젝트의 가치는 엔지니어링·학습 + 체계적 규율·리스크 통제 자동화에 둔다. 그래서 모의투자 우선이 정답이고, 결정론적 리스크 레이어 + 소액이 필수이다. 미국·수급·이벤트를 규율 있게 통합한다는 점에서 단순 차트봇보다 구조적으로 우월하다.
