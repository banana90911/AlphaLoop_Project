## 5. 리스크 엔진
엔진은 파산을 막는 "바닥"만 절대적으로 강제한다. 그 바닥 안에서는 단지 공격적이라는 이유로 거래를 거부하거나 줄이지 않으며, 근거가 강할수록 베팅을 키운다. 이렇게 해서 "근거 있으면 그대로 수행"과 "파산 방지"를 동시에 만족시킨다.

### 5.1 **절대 바닥 — 위반 시 거부 또는 안전 정지**
- 총노출 100% 상한
- 일일 손실 −4% 서킷브레이커. 보유 청산은 정상 가동
- 손절 예약이 실제로 걸린 걸 확인한 뒤에만 매수를 '완료'로 처리
- 받는 정보(시세·잔고)가 이상하면 그 사이클 매매 중단
- **예수금이 음수(미수)면 즉시 안전 정지.** 빌린 돈으로 주식을 들고 있는 상태라 다음 매매를 이어가면 손실이 자본을 넘어설 수 있다. 레버리지 금지의 마지막 방어선이다
- API 오류율 급증 — 조회 요청의 오류율이 50%를 넘으면 그 사이클의 신규 매매 중단
- 점상한가·점하한가 종목 진입 회피
- 보유 중인 종목이 거래정지·관리종목·투자경고/위험으로 지정되면 신규 진입 즉시 금지 및 보유 포지션의 강제 청산 시도 안 함
- VI(변동성 완화장치) 발동 종목은 이번 사이클 건너뛰기 
- VI 발동 시 2분간 단일가 매매라 그 사이 일반 주문이 나가지 않으므로, 해당 종목은 이번 사이클에서만 건너뜀

### **5.2 검사 순서 · 충돌 처리**
규칙들이 동시에 위반될 수 있으므로 고정된 순서로 검사하고, 가장 먼저 걸린 사유 하나로 판정한다.
1. 선행 게이트 — 미체결 매수주문 정리 + 잔고 정합성. 단 보유 종목 방어용 손절 예약은 취소 대상이 아니다. 또한 이 게이트에서 밤사이 스톱이 트리거됐어야 하나 미체결로 남은 보유(개장 갭으로 지정가를 건너뜀)를 감지하면 개장 직후 시장가로 강제 정리한다.

   잔고 대조는 **주식과 현금을 따로 본다.** 근거는 하나다 — 매매는 주식과 현금을 항상 같이 움직인다. 주식이 그대로인데 현금만 변했다면 그건 매매로 설명할 수 없는 돈, 즉 내가 이체했거나 배당이 들어온 것이다. 둘을 한 덩어리로 묶어 놓으면 **입금 한 번에 매매가 며칠 멈춘다** — 잔고 불일치는 사람이 직접 풀어야 하는 정지라서, 신규 진입뿐 아니라 트레일링 상향·본전 상향·시간 청산·논지 무효 청산까지 전부 함께 멈춘다.

   **1-a. 보유 종목·수량 대조** — KIS 실잔고와 DB 내부 포지션을 맞춰본다. 불일치면 `SafeStop`(사람 개입 필수). 여기는 예전과 똑같다.

   **1-b. 현금 대조** — 기대 예수금과 실제 예수금을 맞춰본다.

   ```
   기대 예수금 = 직전 스냅샷 예수금
               + Σ(그 사이 매도 체결 순수취금)
               − Σ(그 사이 매수 체결 순지급금)

   잔차 = 실제 KIS 예수금 − 기대 예수금
   ```

   미체결 매수 주문이 증거금으로 묶일 걱정은 없다 — 이 게이트가 **먼저** 취소하기 때문이다.

   ```
   ├─ 예수금 < 0 (미수 발생)                  → SafeStop
   ├─ 유출액 / 유출 전 총자산 > 50%            → SafeStop (사고 의심)
   ├─ |잔차| < 흡수 임계                     → 무시 (기준선만 재동기화, 누적 로그)
   └─ 그 외 전부                              → CashFlows 기록
                                              + 기준선 재동기화
                                              + Discord 알림
                                              → 사이클 정상 진행 ✅
   ```

   **흡수 임계 = max(1,000원, 자본의 0.01%).** 0으로 두면 안 된다 — 수수료·거래세의 원 단위 절사, 예수금 필드가 여러 개인 문제(예수금총금액/익일정산금액/가수도정산금액, D+2 결제), 계좌 이자 때문에 잔차는 현실에서 절대 0이 안 된다. 1원 차이까지 이체로 기록하면 표가 쓰레기 행으로 찬다. **임계 미만이어도 기대 예수금은 반드시 실제값으로 재동기화한다** — 안 그러면 매일 몇 원씩 쌓여 언젠가 임계를 넘어 가짜 이체가 감지된다. 흡수한 금액은 누적 로그에 남긴다. 계속 한 방향으로만 쌓이면 그건 오차가 아니라 계산식 버그 신호다.

   **왜 "그 외 전부"에서 매매를 안 막는가.** 1-a를 통과한 상태라 남는 위험은 미수와 도난뿐인데 둘 다 위에서 이미 잡힌다. 게다가 입금 방향은 구조적으로 안전하다 — 돈이 실제로 없는데 있다고 믿고 주문하면 KIS가 예수금 부족으로 거부한다. 출금 방향도 자동으로 보수적이다 — 자본이 줄면 `자본 ÷ 20`이 줄고, 현금이 모자라면 총노출 100% 한도가 알아서 막는다. 여기서 한 사이클이라도 막으면 정기 사이클이 하루 한 번이므로 **"그날 전체 차단"**이 되고, 초기 자본을 넣는 첫날조차 거래를 못 한다.
2. KRX 시장 마비 상황 점검 (해당 시, 사이클 완전 스킵):
3. 임시휴장 (전산장애·천재지변·재량 휴장) — KRX 공식 휴장공지 또는 KIS 영업일 API의 그 날 휴장 표시  
- 반장(조기 마감, 예: 12/30 15시 마감) — 사이클 시각이 마감 후 시점이면 스킵      
- 사이드카 발동 중 (5분간 프로그램매매 정지)      
- KRX 시장 전체 서킷브레이커 발동 중
4. 데이터 신선도·시세 이상
5. 우리 측 서킷브레이커 발동 상태 확인 — 당일 손익이 −4% 이하면 발동(5.1). 사이클 자체는 진행하되 신규 주문만 차단하고 보유 청산 로직은 정상 가동한다.

   **분모는 "조정 기준선"이다.**

   ```
   기준선(BaseAsset) = 직전 거래일 마지막 스냅샷의 TotalAsset
   조정 기준선        = BaseAsset + 그 사이 순외부흐름(NetFlowSinceBase)
   당일 손익률        = TotalAsset / 조정 기준선 − 1
   ```

   기준선을 이체 금액만큼 평행이동시키는 이유는 이체가 손익이 아니기 때문이다. 안 옮기면 양쪽으로 다 틀린다.

   ```
   케이스 A — 입금이 진짜 손실을 가리는 경우
     어제 14:30 총자산   10,000,000
     밤에 입금           +2,000,000  → 12,000,000
     오늘 장중 −4% 하락
     오늘 14:30 총자산   11,520,000

     기준선 안 옮김: 11,520,000 / 10,000,000 − 1 = +15.2%  ❌ 손실 완전 은폐
     기준선 옮김:    11,520,000 / 12,000,000 − 1 =  −4.0%  ✅ 정상 발동

   케이스 B — 출금이 가짜 발동을 일으키는 경우
     어제 14:30 총자산   10,000,000
     밤에 출금           −3,000,000  →  7,000,000
     오늘 손익 없음
     오늘 14:30 총자산    7,000,000

     기준선 안 옮김:  7,000,000 / 10,000,000 − 1 = −30.0%  ❌ 가짜 발동, 그날 전면 차단
     기준선 옮김:     7,000,000 /  7,000,000 − 1 =   0.0%  ✅ 정상
   ```

   기준선을 "직전 거래일 마지막 스냅샷의 총자산"으로 못박은 이유가 있다. 예전 정의는 "당일 첫 사이클의 총자본"이었는데, 정기 사이클이 하루 한 번인 이 시스템에서는 그 정의대로면 손익률이 **항상 0%**가 되어 −4% 브레이커가 영원히 발동하지 않는다. 백테스트는 처음부터 전일 종가 기준 총자산을 쓰고 있었으므로, 문서를 백테스트 쪽으로 맞춘 것이다(10-ops 10.9 동일성).

   흡수 임계 미만의 잔차는 기준선을 옮기지 않는다. 그 크기는 대다수가 수수료·이자 같은 진짜 손익이라 손익률에 그대로 잡혀야 한다. 배당·이자·세금 환급도 같은 이유로 옮기지 않는다 — 그건 수익이다.
6. 결정 출력 스키마 검증
7. 하드룰 한도 — 총노출 100%.
8. 종목 상태 점검 — 점상/점하·거래정지·VI·단기과열  
점상한가·점하한가(호가 소멸) 종목 신규 진입 회피 — ±N% 예측이 아니라 지금 호가창에 상대 물량이 있는지로 판정      
- 거래정지·관리종목·투자경고/위험 지정 종목 신규 진입 금지      
- VI 발동 중인 종목은 이번 사이클 건너뛰기      
- 단기과열종목(3거래일 30분 단일가) 신규·추가 매수 금지

### 5.3 모델 이상행동 — 킬스위치
한도는 "이만큼까지"를 정할 뿐이다. 버그로 같은 주문이 쏟아지거나 한 종목에 자본이 몰리는 것은 한도 안에서도 일어난다. 전략이 틀리는 것과 코드가 고장 나는 것은 다르므로, 고장으로 보이는 신호가 잡히면 그 사이클 신규 주문을 전부 취소하고 전체 매매를 정지한다.

| 신호 | 임계 | 왜 이 값인가 |
| - | - | - |
| 단일 주문이 자본의 30% 초과 | 30% | 동일가중이면 종목당 비중이 1/20 = 5%다. 30%가 나왔다면 사이징이 고장 난 것이지 공격적인 것이 아니다 |
| 신규 진입 주문 수 폭주 | `max(동시 보유 상한, 자본 1,000만원당 5건)` | 한 사이클의 정상 최대치는 빈 계좌를 한 번에 채우는 동시 보유 상한이다. 비례식만 쓰면 소액에서 임계가 1건 미만으로 쪼그라들어 정상적인 첫 진입까지 막으므로, 동시 보유 상한을 하한으로 깐다 |
| 같은 종목에 매수·매도 동시 제안 | — | 방향 충돌은 전략 판단이 아니라 명백한 버그다 |

임계는 `config/risk_params.toml [anomaly]`에 둔다. 이 정지는 시장 탓이 아니라 우리 코드 탓이므로 자동 재개하지 않는다.

**어떤 값이 손잡이가 되는가 (방어선).** *매매 결정을 바꾸는 값만 `risk_params.toml`에 두고 7개 제약(09-eval 9.3)에 넣는다. 그렇지 않은 값만 코드 상수로 뺀다. 어떤 값이 나중에 매매를 바꾸게 되면 그 순간 손잡이로 승격시키고 7개를 다시 센다.*

이 기준으로 **50% 유출 SafeStop과 흡수 임계는 손잡이가 아니다.** 50%는 튜닝 파라미터가 아니라 "사람을 부르는 선"이라 정확할 필요가 없고 대략 맞으면 된다 — 자본 절반 이상을 하룻밤에 옮기는 건 몇 년에 한 번 있을까 말까 한 일이고, 그때 멈추는 건 오히려 옳다(자본이 반토막 나면 20슬롯 동일가중 사이징의 전제가 통째로 바뀐다). 흡수 임계도 틀려봐야 서킷브레이커 판정에 자본의 0.01%p(임계 −4%의 1/400), 종목당 배분액에 1,000만원 기준 50원을 움직일 뿐이라 수량이 바뀔 확률이 사실상 0이다.

### **5.4 재개 · 복구 절차**
정지만큼 어떻게 다시 켜는가가 중요하다. 자동매매가 정성 판단 없이 재개되려면 재개 조건도 결정론이어야 한다.  
기본 원칙: 시장 변동에 기인한 정지는 자동 재개, 시스템 자체의 신뢰성 문제는 사람 개입 필수.

| 트리거 | 정지 범위 | 재개 조건 |
| - | - | - |
| 일일 손실 −4% | 신규 진입만 차단 | 날짜 경계에서 자동 해제 |
| API 오류율 급증 | 신규매매 중단 | 오류율이 50% 아래로 30분 유지되면 자동 재개 |
| 보유 불일치·데이터 오류 | 전체 매매 정지(`SafeStop`) | 사람 개입 필수. 운영자가 원인 확인 + config 플래그 수동 해제 |
| 대형 현금 유출·미수 발생 | 전체 매매 정지(`SafeStop`) | 사람 개입 필수. 원인 확인 후 CLI로 흐름을 라벨링(`python -m ops.cashflow`) |
| 평범한 입출금 감지 | **정지 없음** | 기록·알림만 하고 그대로 진행. 라벨은 며칠 뒤에 붙여도 된다 |
| 모델 이상행동 | 전체 매매 정지(`SafeStop`) | 코드 고장이므로 원인을 고치기 전에는 재개하지 않는다 |

`SafeStop` 발생·해제는 테이블에 시점·원인·해제자·해제 사유를 적재해 사후 감사를 가능하게 한다.
